Snoek–VerBerkmoes Family Vault

A research vault deconstructed from Ruth Taber’s History of the Coffin, Samargia, Snoek, VerBerkmoes Families (timeline document, dated 25 Dec 2025). The original PDF is preserved in _Archive/.

We are the chosen. In each family, there is one who seems called to find the ancestors. To put flesh on their bones and make them live again. We are the storytellers of the tribe. — Opening of the source document

How this vault is organized

FolderWhat lives there
00-Index/This Home page, the four family Maps of Content (MOCs), and shared reference notes (Dutch naming conventions, regional geography).
01-People/One note per ancestor, organized into family-line subfolders. YAML frontmatter holds birth/death/parents/spouse so the data is queryable.
02-Places/Towns, villages, regions — Devon, Hulst, Goes, Roden, Grand Haven, etc.
03-Historical-Context/World/national events that shaped the family (Mayflower, French Revolution, Dutch Secession, WWI/II, etc.).
04-Local-History/Grand Haven, Spring Lake, Ferrysburg landmarks, businesses, and ships from the timeline.
05-Family-Groups/One note per marriage/household. Useful for ahnentafel-style browsing.
06-Timeline/Year-indexed stub notes — gives a chronological view of any year.
07-Sources/Census records, newspaper clippings, vital records, citations.
08-Media/Photographs and scans extracted from the source.
09-Research-Log/Open questions, gaps, contradictions, things to follow up on.
_Archive/The original PDF, untouched.
_scripts/The Python scripts used to extract this vault from the PDF. Re-runnable; the parsed people.json is also kept here for reference.

Family Maps of Content

  • MOC-Coffin — English origins (Devon → New England → Wisconsin/Michigan)
  • MOC-Samargia — Croatian origin (joins the family via Anna Samargia ↔ Clarence Snoek, 1932)

Each MOC now opens with a direct-line Mermaid ancestry tree (7 VerBerkmoes generations, 8 Coffin generations, 4 Snoek generations, 1 Samargia).

How to read this vault

  1. Start with a MOC above to get oriented in one family line.
  2. Click any name to open their personal note. From there, parents and spouses are wikilinks — keep clicking to walk the tree.
  3. Use the Graph view (Obsidian’s left sidebar → graph icon) to literally see the family tree as a connected graph. Try filtering by tag — e.g. tag:#snoek shows only the Snoek line.
  4. Use the search (Ctrl+Shift+F) for any name, place, or year.
  5. Add to it. This vault is designed to grow. When you find new sources, drop them into 07-Sources/ and link them from the relevant person notes. When you have a research question, add it to 09-Research-Log/Open-Questions.md.

Person-note features

Every person note has:

  • YAML frontmatter with name, family_line, generation, birth_date, birth_place, death_date, death_place, father, mother, spouses[], tags[], source. Queryable with the Dataview plugin.
  • Wikilinked parents resolved via fuzzy matching that respects generation, birth year, and middle-name initials, so “Adriaan A Verberkmoes” links to the right gen-6 Adriaan and not his great-grandson.
  • Wikilinked spouses with their own birth/death info inline.
  • Auto-computed Children section built from the reverse parent index.
  • Timeline section (Phase 3a) — chronological events from pp. 7–164 attached to the right person, including censuses, WWII draft cards, immigrations, etc.
  • Multiple marriages with divorce dates where present.
  • Source provenance at the bottom of each note (page range + raw “Parents” line if non-trivial, so you can spot OCR or transcription errors).

Place-note features (Phase 3e+)

After the Phase 3 deconstruction, place notes were further consolidated and enriched:

  • Aggressive normalization — every place string is run through a 6-phase pipeline that strips ages, addresses, person-name leakage, ward/district codes, and county-into-city bleed. State abbreviations and common typos (Wisc/Ill/Ind/Orgon) are expanded. Result: 199 → 189 fully canonical City, State (or City, State, Country) entries.
  • Curated geo enrichment — for the 47 most-referenced places, _scripts/places_gazetteer.json provides accurate county, state, country, latitude, longitude, wikipedia URL, founding year, and a brief genealogical context note.
  • County hub notes — 02-Places/_Counties/ contains one note per unique county, aggregating every place + every family event in that county. Ottawa County, Michigan alone aggregates 5 places (Grand Haven, Holland, Spring Lake, Ferrysburg, Nunica) and 441 events.
  • “Other places in this county” cross-reference on every place note that has a county.
  • “Local history” and “Census records” sections on every place note, automatically populated from narrative and source notes that match the place name.

Phase 5 — image extraction

The source PDF contains 276 embedded photos and scans (newspaper clippings, family portraits, ship photos, building photos, ancestry charts). All have been extracted into 08-Media/ and automatically embedded into the relevant notes:

  • Narrative notes (03-Historical-Context/, 04-Local-History/) embed the image(s) on their source_page.
  • Census source notes (07-Sources/Census/) embed the image(s) on their source page.
  • Person notes (01-People/) embed images from every page referenced in their Timeline section. So Clarence Snoek (1905), who has Timeline events on pp. 104, 143, and 149, gets all 11 images from those three pages.

Images are embedded with a 400px width hint and the source page caption. Re-running embed_images.py is idempotent.

Phase 4 — source corrections

A small people_corrections.json overlay file applies hand-curated fixes for the 4 known parent-attribution errors in the source PDF (Ruth Louise Snoek, William VerBerkmoes 1888, Adrian VerBerkmoes 1880, Susan A VerBerkmoes 1881). The original source values are preserved in each affected person note’s footer with a ⚠️ warning marker, so the correction is auditable.

Re-running the extraction

All scripts live in _scripts/ and are re-runnable. If Ruth issues an updated PDF in the future:

  1. Replace the PDF in _Archive/
  2. Re-extract the text: 
    python _scripts/parse_groupsheets.py
python _scripts/parse_chronological.py
python _scripts/parse_narratives.py
  3. Re-render the notes: 
    python _scripts/generate_notes.py
python _scripts/generate_narratives.py
python _scripts/generate_sources.py
python _scripts/generate_places.py
  4. Re-extract images and embed them: 
    python _scripts/extract_images.py
python _scripts/embed_images.py
  5. Run the audit: 
    python _scripts/audit.py

pypdf and Pillow are the only Python dependencies.

Known limitations to be aware of

  • A few duplicate stubs may exist — when the source PDF used inconsistent spellings (e.g., "Lizzie" vs "lizzie", Williem vs Willem), the matcher occasionally creates two notes for the same person. Use Obsidian’s “rename and update links” to merge them as you encounter them.
  • CENSUS events appear only in source notes (07-Sources/Census/), not in the per-person Timeline sections. Each census source note links to its household members, so Obsidian backlinks let you find all censuses for a person.
  • Source typos — the four known parent-attribution errors are now corrected automatically by the corrections overlay. New typos discovered later can be added to _scripts/people_corrections.json.
  • Place geo coverage is 25% — 47 of the 191 places have curated geo data (county, coordinates, Wikipedia). The remaining 144 are mostly single-event places. To bring coverage to 100%, run a Wikipedia/Wikidata enrichment script (not yet built — would be Phase 6).
